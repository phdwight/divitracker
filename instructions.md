# GENAI Code Generation Guidelines

These guidelines define the required standards for any code, documentation, or tests generated by AI contributors. All generated output **must** follow these rules unless explicitly overridden by the human maintainer.

---

## 🧩 Coding Standards

### 🐍 Python Version & Style
- All code **must use Python 3** and follow the **latest Python idioms**, including:
  - f‑strings  
  - dataclasses where appropriate  
  - type hints everywhere  
  - context managers  
  - pathlib instead of `os.path`  
  - list/dict/set comprehensions  
  - modern exception handling patterns  

- Code must be **lint‑clean** using:
  - `flake8`
  - `black` (PEP 8 formatting)
  - `isort` for import ordering
  - `mypy` for type checking (when applicable)

### 🧱 Architecture & Structure
- All application code must follow the **Flask** framework structure:
  - `app/` directory with `__init__.py`
  - Blueprints for modular routing
  - Jinja2 templates (if applicable)
  - Config classes for environment separation

- **SQLite** must be used for persistent storage unless otherwise specified.
  - Use SQLAlchemy ORM or raw SQL with parameterized queries.
  - Migrations should be handled via Flask‑Migrate (if ORM is used).

### 🧭 SOLID Principles
All classes must adhere to:

| Principle | Requirement |
|----------|-------------|
| **S**ingle Responsibility | Each class has exactly one reason to change. |
| **O**pen/Closed | Classes should be extendable without modification. |
| **L**iskov Substitution | Subclasses must be usable anywhere their parent is expected. |
| **I**nterface Segregation | Avoid “fat” interfaces; keep them focused. |
| **D**ependency Inversion | Depend on abstractions, not concrete implementations. |

### 🛡 Defensive Coding
- Validate all inputs.
- Never assume external systems behave correctly.
- Use explicit error handling with meaningful messages.
- Avoid side effects unless documented.
- Logging must be structured and contextual.

## 📘 Documentation Requirements

### README Maintenance
- The `README.md` **must be updated** whenever:
  - new features are added  
  - APIs change  
  - dependencies change  
  - environment variables change  
  - setup or run instructions change  

### Documentation Style
- Use clear, concise, developer‑friendly language.
- Include:
  - project overview  
  - architecture summary  
  - setup instructions  
  - run/test commands  
  - API endpoints (if applicable)  
  - examples  

---

## 🧪 Testing Requirements

### Test Framework
- All tests must use **pytest**.
- Tests must be placed in a `tests/` directory.
- Tests must follow:
  - AAA pattern (Arrange–Act–Assert)
  - descriptive test names
  - fixtures for reusable setup
  - mocking for external dependencies

### Test Coverage
- Every new feature must include tests.
- Tests must be updated when:
  - logic changes  
  - APIs change  
  - database schema changes  

### Test Quality
- Avoid brittle tests.
- Prefer behavior‑based testing.
- Ensure tests run deterministically.

---

## 📦 Output Expectations for GenAI

When generating code, GenAI must:

- Produce **complete**, runnable code — not fragments.
- Include all necessary imports.
- Provide explanations only when requested.
- Maintain consistent naming conventions.
- Ensure code, tests, and documentation are aligned.
- Avoid deprecated patterns or libraries.
- Prefer clarity over cleverness.
